# Decisions

Short records: what was decided, why, and who decided. Newest at the bottom.
When the plan is silent, pick the simplest option that fits the design, record it here, and keep going.

| D32 | Corrupt save (unparseable or not a JSON object) is copied to `save.corrupt.json`, removed and replaced by a new game with a logged warning; wrongly typed fields fall back to defaults | Never crash, never silently lose the bad file | Bea (TASK-008) |
| D33 | Persistence is opt-in: `Main._enter_tree` calls `GameState.enable_persistence()` (export `use_save_file`); autosave on `round_summary` and on window close. | D34 | Mod menu: opening saves `Engine.time_scale` and sets economy.json `mod_menu_time_scale`; closing restores the saved value. Insert toggles, Esc also closes; the menu keeps running at any round state (`PROCESS_MODE_ALWAYS`) | Task spec; restoring the saved value avoids fighting other slow-mo effects | Rex / TASK-010 |
| D35 | Mod menu numbers use a short format rounded **down** to one decimal (1.29K → "1.2K"); the injector bar is cosmetic (1.2 s real time, cheat already active), kept as a UI constant rather than economy data | Cash is never shown higher than it is; the bar is not a balance value | Rex / TASK-010 |
| D36 | Wallhack: outline = `next_pass` shader drawing neon box edges (from BoxMesh 3×2 UV cells) + faint fill with depth test off; range re-checked every 0.2 s by a Scanner node under the player; `whole_map` bool at max level (range = ∞); health bars from level 8 (data) as billboard Sprite3Ds | Cheap, works on Compatibility, fits voxel bots; "top levels" read as the last three | Rex / TASK-012 |
| D37 | ChatSystem derives `first_match` (first freeze ever), `first_cash` (first positive cash change), `round_start`/`round_live` (each freeze/live) and `cheat_first_use` (first `cheat_toggled(id, true)` per cheat) from EventBus signals; "first" gates are stored in `GameState.chat_flags` as `event:<name>`; every once-only flag is written when its (last) line posts, not when it is queued | No emitter needed in other modules; once-only survives saves (TASK-013) | Rex |
| D38 | Bot-channel mute is a player setting in `user://settings.cfg` (`[chat] muted_channels`), not in the save; muted lines stay in history and reappear in the log when unmuted | Settings are not progress; Phase 5 settings menu can reuse the file (TASK-013) | Rex |
| D39 | Without Auto Bhop a jump needs a fresh press (`is_action_just_pressed`); with it, holding jump re-jumps on the landing frame | Plan: Auto Bhop level 1 is "hold jump to hop", which only means something if holding does not already hop | Rex / TASK-011 |
| D40 | Auto Bhop speed: each hop multiplies horizontal speed by `1 + hop_speed_gain`, capped at effective move speed × `max_hop_speed_mult` (1.2 → 2.5, new cheats.json effect) until `uncapped` at max; a hop never slows the player; while bhopping, air strafing keeps speed instead of bleeding it to walk speed | Plan says "speed builds every hop, no cap" at max, so lower levels need a data-driven cap; Speed Hack raises the cap too | Rex / TASK-011 |
| D41 | Infinite Ammo "never reload" = `infinite_reload` makes reload time 0 (the empty mag refills on the last shot); switching it on mid-reload finishes that reload | Simplest reading of the plan row; reuses the weapon modifier hook | Rex / TASK-011 |
| D42 | `--dev-cash` debug flag (pass after `--`: `godot --path . -- --dev-cash`): starts a fresh in-memory game with 50,000 cash and 400 lifetime kills (unlocks Speed Hack, Infinite Ammo, Auto Bhop, Wallhack) and disables the save file, so a real save is never read or overwritten. Constants live in `scenes/main.gd` (not balance data). The flag currently also works in release exports; harmless while it only changes in-memory state, but once achievements/Steam stats exist (Phase 5) it must also disable them or be limited to debug builds | Gate 2 reviewers should not have to grind 400 kills to feel every cheat | Quinn / TASK-014 |
| D43 | Air movement is Source/CS air acceleration (`air_accel` 12 = sv_airaccelerate, `air_speed_cap` 0.72 m/s ≈ 30 u at 6 m/s = 250 u): only speed along the wish direction is capped, so manual strafe jumping builds speed with no cap. Ground movement is unchanged. A jump press is queued for the next physics tick only (replaces D39's `is_action_just_pressed`), and jump is also bound to mouse wheel up/down, so hand bhopping takes CS timing. Supersedes D40 | Old bhop gave speed from cheat levels, not strafing, and did not feel like CS | Claude |
| D44 | Auto Bhop: level 1 = hold jump to hop on every landing tick (as D39). `autostrafe` (0 → 1, replaces `hop_speed_gain`) strafes for you in the air: a right-angle push toward the move direction (straight ahead when idle, alternating sides), keeping that fraction of the best gain, up to `max_hop_speed_mult` × effective move speed until `uncapped` at max. Pressing back falls back to normal air control so you can brake; auto-strafe never slows the player | Auto-strafe is a real CS cheat, and it keeps per-level progression | Claude |
| D45 | Aimbot / Triggerbot / Spinbot run from a per-player `DriverCheat.Driver` node each physics tick and only act while the player is alive with no menu open; cheat shots use `WeaponManager.cheat_fire()` so round state, menus, fire rate and ammo still apply. Aimbot locks the visible head nearest the crosshair within `fov_deg`, turning `snap_speed` of the remaining angle per tick; `instant_headshot` = weapon `force_headshot` modifier. Spinbot = snap to the nearest visible bot in any direction and fire every `spin_interval_s`, no wait from `constant_fire`; the view is not spun between shots | These cheats had data but no code; one shared driver keeps them small and consistent | Claude |
| D46 | Hitbox Expander scales only the invisible head hitbox via static `Bot.head_hitbox_scale` (read on spawn, pushed to live bots on apply/remove) | Bots outlive cheat toggles and new waves spawn mid-round; a static avoids bots reading CheatSystem | Claude |
| D47 | Loot = bonus cash drops: each kill drops a pickup with `loot.drop_chance`, worth `loot.cash_mult` × that kill's cash, on top of the normal instant kill reward; collected within `pickup_radius_m`, gone after `lifetime_s` or at round end (parented to the BotSpawner). Loot Magnet pulls pickups within `radius_m` at `magnet_speed_m_s` | The game had no loot, so Loot Magnet had nothing to do; bonus-only drops make it useful without rebalancing kill income | Claude |
| D48 | God Mode lives in Player: `set_god_mode(seconds_per_kill, permanent)`; each kill sets invulnerability to the longer of what is left and the grant; falling out of the map bypasses it | Simplest reading of the data; a fall must still end the life or the player falls forever | Claude |
| D49 | Noclip is a toggle on a new `noclip` action (V, as in Source): flight with collision off, a per-round `burst_s` budget refilled at freeze, and a depth limit per pass of `max_wall_thickness_m` + the body's size along the move, measured from where the player entered the geometry (backing out is always allowed). Flight cannot end inside geometry | Without a per-round budget, re-toggling would make `burst_s` meaningless; measuring from the entry point lets the player back out of a too-thick wall | Claude |
